# ゲームの品質基準（公開の条件）

すべてのゲームは、公開する前に、または大きく直したあとに、このチェックリストを満たします。
「自動」は `tools/tests/`（TEST_PLAN.md）で確かめる方法、「手動」は人がスマホの実機で確かめる方法です。
自動テストは、手動の確認の代わりにはなりません。手触り・難易度・気持ちよさは、必ず実機で遊んで確かめます。

## チェックリスト

| ID | 条件 | 合格の基準 | 自動（Playwright） | 手動 |

| Q-2 | チュートリアル | 最初のステージまたは最初の30秒で、主な操作を1つずつ実際にやらせる（文章だけでは不合格） | `?debug` のフックで、チュートリアルの各手順が進むことを確かめる | 手順を飛ばしても詰まらないか |

## 判定のしかた
- 公開できるのは、Q-1〜Q-8 と Q-10〜Q-17 が全部 ✓ のときだけです。△ が残る場合は、`docs/AUDIT.md` の表に理由を書き、オーナーの了解を得ます。
- 手番制のゲームの Q-5 は「離れても状態が保存される」で ✓ とします。
- Q-9（BGM）は、オーナーが曲を用意するまで判定しません。

## 各ゲームが用意する `?debug` のフック（自動テストのため）
今の `window.__neji`（neji:1880-）、`window.__hole` の方式にそろえ、`window.__kb` に置きます。
```js
window.__kb = {
  ready: () => bool,                 // 最初の画面が出た
  state: () => ({ mode, score, time, over, stage, paused }),
  win(), lose(),                     // すぐにクリア・失敗にする
  step(n),                           // 決まった手を n 回進める（ソルバーかボット）
  tutorial: () => ({ step, done }),
};
```
フックは `?debug` のときだけ作ります。本番の動きには影響させません。
