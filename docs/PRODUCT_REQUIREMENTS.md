# プロダクト要件

優先度：**S** = Phase 1〜2 で必須（これがないと出せない）／**A** = Phase 3 までに入れる／**B** = あとで、余裕があれば
前提：静的ホスティングのみ、Spark（無料）プラン、Cloud Functions なし、広告なし、課金なし、日本語と英語、スマホ優先。

## 0. オーナーの決定（2026-11）
1. Spark プランのまま。スコアの信頼性はクライアント側で守る（もっともらしさ・seed・ゲームごとの上限・外れ値の除外）。
2. フレンドは、フレンドコードを交換して登録する。
3. ステージエディタは、共有コードで受け渡すだけ。サーバーに公開して投稿する機能は今は作らない。
4. 通知はアプリ内の「お知らせ」だけ。プッシュ通知はしない。
5. フッターのお問い合わせは、GitHub Issues（`Seg1GPT0Jpn/nejihodoki`）へのリンクにする。メールは載せない。
6. 人気は、ゲームごとの匿名のプレイ回数だけで数える。それ以外の分析はしない。
7. BGM は今は入れない（あとで、ちゃんと作った曲を入れる）。効果音は今のまま。音量の設定は全体と効果音にし、BGM の欄は見えない状態で用意しておく。

## 8. ゲームごとの完成の条件
すべてのゲームで GAME_QUALITY_STANDARDS.md の Q-1〜Q-14 を満たすこと。そのうえで、監査の結果からとくに必要なもの：

| ゲーム | S | A |
| --- | --- | --- |
| neji | 共通の音のキー（R6）、日本時間のデイリー（R7）、`cloud.js` に統合（R8）、止まっているときは描画しない（R16） | 影の画質の設定 |
| blocks | 遊び方（初回に3ステップ）、終わった盤が復活する問題（R3） | デイリー（seed で同じピースの順番） |
| drop | 途中の盤の保存（`kusoge.drop.state`） | デイリー |
| raft | 書き込みの間隔（R2）、死んだいかだが復活する問題（R3） | 自動の画質調整 |
| gates | フィールドごとのマージ（R4） | 最初のステージをチュートリアルに |
| n59049 | `bestTile` の同期、遊び方 | デイリー |
| water | フィールドごとのマージ（R4） | デイリー |
| parking | 遊び方の画面、フィールドごとのマージ | デイリー |
| hole | ハブの記録の表示（R9）、ランキングの値（R10）、フィールドごとのマージ（R4）、RTDB のルール（R11） | 部屋の掃除（R13）、送信量を減らす（R12） |

## 9. 新しいゲーム（Phase 4）
順番は、脱出ゲーム → タワーディフェンス → 物理パズル → ミニゴルフ → リズム。どれも最初から `KoboGame` の約束事に従い、GAME_QUALITY_STANDARDS.md をすべて満たしてから公開します。リズムゲームは BGM が必要なので、オーナーが曲を用意してからにします。

## 10. あとでやるもの（B）

- BGM（オーナーが曲を用意したら）
